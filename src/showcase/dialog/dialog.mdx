# Dialog

**Import:** `import { MatDialogModule } from '@angular/material/dialog';`

A dialog is a component you open from code. You inject `MatDialog`, call
`open()` with a component class, and Angular Material renders that component in
a CDK overlay above the page with a focus trap and a backdrop.

```ts
const ref = dialog.open(ConfirmDialog, { width: '360px', data: { id: 42 } });
ref.afterClosed().subscribe((result) => console.log(result));
```

## Try it

Open the dialog, change the controls, open it again. The result under the button
comes from `afterClosed()`.

## The four structural directives

A dialog component is plain markup plus four directives. They give you a sticky
title, a scrollable middle and an action row pinned to the bottom.

```html
<h2 mat-dialog-title>Delete invoice?</h2>
<mat-dialog-content>This cannot be undone.</mat-dialog-content>
<mat-dialog-actions align="end">
  <button matButton mat-dialog-close>Cancel</button>
  <button matButton="filled" [mat-dialog-close]="true">Delete</button>
</mat-dialog-actions>
```

`mat-dialog-close` closes the dialog and passes its value as the result. With no
value it closes with `undefined`, which suits Cancel.

## Passing data in

The dialog component has no inputs. It receives data through the `data` config
option and reads it with the `MAT_DIALOG_DATA` token.

```ts
readonly data = inject<ConfirmData>(MAT_DIALOG_DATA);
```

## Getting a result out

`afterClosed()` emits once, after the closing animation, with the value that
closed the dialog. It emits `undefined` when the user presses Escape or clicks
the backdrop, so always handle that case.

<Example of={DialogStories.ConfirmDialogStory} />

```ts
const ref = this.dialog.open<ConfirmDialog, ConfirmData, boolean>(ConfirmDialog, {
  width: '360px',
  data: { title: 'Delete invoice?', message: '...', confirmLabel: 'Delete' },
});

ref.afterClosed().subscribe((confirmed) => {
  if (confirmed) this.remove();
});
```

The three type parameters on `open<T, D, R>` are the dialog component, the shape
of `data`, and the result type. Fill them in and the compiler checks both ends.

## A form inside a dialog

Build the form in the dialog component, then close with the form value. Inject
`MatDialogRef` and close from code instead of a `mat-dialog-close` button, so
you can block the close while the form is invalid.

<Example of={DialogStories.FormInDialog} />

```ts
private readonly ref = inject<MatDialogRef<ProfileDialog>>(MatDialogRef);

save() {
  if (this.form.valid) {
    this.ref.close(this.form.getRawValue());
  }
}
```

Give the submit button `type="submit"` and the cancel button `type="button"`, or
Cancel will submit the form.

## Configuration

<Example of={DialogStories.Configuration} />

```ts
dialog.open(MessageDialog, {
  width: '640px',
  disableClose: true,
  autoFocus: 'dialog',
});
```

Set `width` in CSS units, or `maxWidth` if you want the dialog to shrink on
narrow screens. The default `maxWidth` is `80vw`.

## API you will use

| Member | Type | What it does |
| --- | --- | --- |
| `dialog.open(Component, config)` | `MatDialogRef<T, R>` | Opens the dialog and returns its reference |
| `config.data` | `D` | The value injected as `MAT_DIALOG_DATA` |
| `config.width` / `maxWidth` | `string` | Panel size, in CSS units |
| `config.disableClose` | `boolean` | Blocks Escape and backdrop clicks |
| `config.autoFocus` | `'first-tabbable' \| 'dialog' \| 'first-heading'` | Where focus lands on open |
| `config.ariaLabel` | `string` | Accessible name when there is no `mat-dialog-title` |
| `ref.afterClosed()` | `Observable<R \| undefined>` | Emits the result once, after the close animation |
| `ref.close(result)` | `void` | Closes from code with a result |

## Accessibility

Angular Material gives you a focus trap, `role="dialog"`, and focus restoration
to the element that opened the dialog. You supply the name.

- `mat-dialog-title` is wired to `aria-labelledby` automatically. Use it.
- If the dialog has no visible title, pass `ariaLabel` in the config instead.
- `autoFocus: 'first-tabbable'` is the default and is right most of the time.
  Switch to `'dialog'` when the first control is destructive, so nobody deletes
  a record by pressing Enter on reflex.
- Do not set `tabindex` on anything inside the dialog. The focus trap already
  cycles through the natural tab order.

## Common mistakes

1. **Assuming `afterClosed()` always emits your result.** It emits `undefined` when the dialog is dismissed. Check before using the value.
2. **`disableClose: true` with no close button.** The dialog becomes a trap. Only lock a dialog when you render your own way out.
3. **Passing data with `componentInstance`.** Setting fields on `ref.componentInstance` after open runs after the first change detection. Use `config.data` instead.
4. **A Cancel button inside a `<form>` with no `type`.** It defaults to `type="submit"` and submits the form. Write `type="button"`.
5. **Forgetting `MatDialogModule` in the dialog component's own imports.** The component that renders `mat-dialog-title` needs the module, not only the component that calls `open()`.
